批量文件改名助手 1.2
Windows 10/11 64 位便携版 · 离线运行

1.2 新增与修复
• 顶部“环境与安全自检”：在当前电脑实际运行模拟改名、复制、移动、撤销和回收站检查；无需命令或开发环境。
• “导出预览清单 TXT”：导出全部行的路径、状态和哈希，仅创建新文件，绝不覆盖已有文件。
• “最近批次详情”：直接查看结果、错误和备份 / 保留位置。
• 启动与界面异常会尝试保存中文诊断日志，用户目录不可写时尝试临时目录。
• 修复旧版跨磁盘中断恢复路径，改用校验复制与安全回收；检查损坏日志后才允许恢复。
• 不完整重复字段拒绝猜测；字段已出现但值为空，不再当作真正“缺失”。
• 非模板规则不再受未使用序号溢出影响；长路径清理可退到同目录短保留名称。
• 阻止文件操作触碰软件自己的日志及预设目录，保护撤销记录。
• 进度更新限制频率，减少大量小文件对界面消息队列的压力。

一、打开及查看规则
把“批量文件改名助手.exe”下载或传到 Windows 电脑，双击运行。
已附带 .NET 运行时，不用安装开发环境、Python、Node 或数据库。首次运行会解压附带的运行库到用户临时目录。
软件内有“文件与规则”“预览与执行”“找文件规则说明”三个标签页。
在改名区域或预览页点击“命名规则与试算”，也可以按 F1：查看当前生效规则，输入一个文件名试算。试算不读写文件。
源码压缩包仅供保留及维护，日常使用只需要 EXE。

二、你的 U 范围与 nsweep 示例
1. 选择源文件夹，文件通配符填写 *.h5。
2. 默认不包含子文件夹；需要向下扫描时主动勾选。
3. 条件选“数值范围（包含边界）”，字段 U，值 / 下限 3.5，上限 4.5。
   软件默认已经填好此条件。修改现有条件后点击“更新选中条件”；新增条件用“添加条件”。
4. 改名方式选“设置字段值”，字段名 nsweep，新值 100。
5. 选择原地改名、移动原文件或复制文件。移动 / 复制必须选目标文件夹。
6. 扫描生成预览，核对原路径、新名称、目标路径、原因和状态。
7. 仅勾选确实需要执行且状态合法的行，点击执行并核对确认清单。

U_1.000 不在范围内，不会选中。3.5 和 3.500 数值相等；3.500、4.000、4.500 都包含在范围内。
原名：dimer_2_j_1.000_U_4.000_L_200_ratio_0.150_filling_1010_nsweep_251_mps.h5
新名：dimer_2_j_1.000_U_4.000_L_200_ratio_0.150_filling_1010_nsweep_100_mps.h5

三、更通用的找文件规则
文件通配符：*.h5 找 h5 文件，* 或 *.* 找所有文件，包括无扩展名文件。
多个类型用分号：*.h5;*.txt;*.csv。类型之间满足任意一个即可。
* 表示任意长度文本，? 表示一个字符。通配符不填写路径。

包含：名称中有指定文本即可。排除：有指定文本就不选。通配符：按整个文件名模式匹配。
例如添加“文件名包含” dimer_2，再添加“文件名不包含” backup。
还支持文件名开头 / 结尾、字段存在 / 缺失、字段值包含 / 不包含。
普通条件与可选正则筛选之间采用“并且”：所有条件都满足才选中。
缺少字段时，普通字段比较不匹配；只有明确的“字段缺失”条件用于查找缺少字段的文件。
默认忽略英文字母大小写，可启用区分大小写。

字段自动识别：字段_值、字段-值、字段=值；可有空格、括号和分号边界。
例如 U_4.000、U-4.000、U=4.000。支持 dimer、j、U、L、ratio、filling、nsweep 以及中文字段等。
字段名以字母或汉字开头，可含数字、下划线、点、短横线，最多 80 字符。
默认格式中，文本值在下一个分隔符处结束。值本身含复杂分隔符时请使用自定义字段正则。
重复字段、空值或不明确格式不会猜测使用哪个。
数值比较使用精确十进制 / 科学计数法，范围包含上下边界，不会把极小数当成零。
字段等于 / 不等于可选自动、强制数值、按文本比较；文本模式能区分 001 与 1。

高级字段提取例：识别 U[4.000] 和 nsweep[251]：
(?<![\p{L}\p{N}]){field}\[(?<value>[^\]]+)\]
{field} 代表当前要查找的字段，(?<value>...) 标记真实字段值。此设置同时用于字段筛选及设置字段值。

可照填的正则筛选例：
^dimer_2_.*_nsweep_251_.*\.h5$
表示以 dimer_2_ 开头、含 _nsweep_251_ 并以 .h5 结尾。
正则筛选作用于完整文件名。正则错误或单次匹配超过 200 毫秒会停止，禁止执行该次预览。

四、更通用的命名规则
每批只用一条改名规则，扩展名不参与修改：
• 设置字段值：只替换指定字段的值。默认字段缺失不处理；主动开启“缺失时追加”才增加字段。
• 文本替换 / 正则替换：可替换全部或仅第一处；替换为空表示删掉指定文字。
• 添加前缀 / 后缀：加在扩展名前；例如 原名_归档.h5。
• 名称转小写 / 大写、去除首尾空格：扩展名仍保持原样。
• 模板与编号：将多个信息组合成一个新名字。

模板可照填：实验_{field:U}_{index:0000}_{name}
{name} 原名（不含扩展名）
{parent} 直接父文件夹名
{field:U} 名字里 U 的原始值
{index} 序号；{index:0000} 至少四位，不截断更大的序号
{modified:yyyyMMdd_HHmmss} 修改时间
{created:yyyyMMdd} 创建时间
{{ 和 }} 输出普通大括号。
模板不用重复写扩展名，软件自动加回；未知变量会报错，缺失字段会标记无法改名。
编号按匹配文件的相对路径排序，支持起点和步长；取消勾选会留空号，不重新编号。
时间使用本机文件系统时间；试算框用示例目录和当前时间，实际结果以扫描为准。
正则替换引用分组使用 ${1}、$1 或 ${组名}；数字紧跟分组时优先用 ${1}100。

默认保护 .tar.gz、.nii.gz、.fits.gz、.csv.gz 等复合扩展名，可在设置中修改列表。
扩展名大小写保持不变；.env 这类单个前导点名称视为无扩展名。
不同文件命名习惯可能有歧义，先用“命名规则与试算”，再检查真实预览。

五、操作方式、预览与覆盖
原地改名：保留在原文件夹，仅名称变化；所有源先暂存再提交，支持循环和大小写改名。
移动原文件：目标生成并整批校验成功后，源暂存送入回收站；原路径不再保留文件。
复制文件：源文件不动，目标生成完整副本。
递归移动 / 复制保留相对目录。跳过软件备份 / 保留 / 临时文件、符号链接和目录联接；独立目标子目录也跳过。

预览只读，不写文件、不创建目标目录；会读取匹配文件原始字节计算 SHA-256，因此大文件扫描需要时间。
文件内容仅用于字节一致性校验，不解析 HDF5、图片、文本或任何数据格式，也不改写内容。
非法名、完全相同路径、批内重名等状态不能执行。更改规则或路径后必须重新扫描。
移动 / 复制到其他目录时，可以保留原名称；只改变存放位置仍是有效操作。
多个源生成同一目标时一律禁止，不得通过覆盖解决。
覆盖默认关闭；主动开启后需重新扫描，执行前显示覆盖数量与完整清单并再次确认。
旧目标先移入其原目录下“.批量改名助手_备份_批次号”。备份不会自动删除。

六、完整性、取消、撤销和回收站
执行前重新核对预览指纹，包括相同大小和修改时间但内容变化的情况。
复制先写临时文件，核对长度、源复制流 SHA-256、重新读取临时副本 SHA-256，再提交最终名称。
提交后核对最终目标，并在整批结束前再核对一次。移动所有源暂存会留到整批核验成功。
发生错误或取消时尝试整批回滚；若外部路径或内容变化阻止恢复，则保留文件并说明冲突。
异常目标会隔离保留；取消中的残缺副本不会留在最终文件名下。

需要清理的移动源暂存、撤销副本、取消后的临时副本、删除的规则预设，均走回收站流程。
先移入相邻“.批量改名助手_保留_批次标记”，再请求 Windows 系统回收站。
程序要求回收，并在删除前回调中拒绝永久删除；回收站不可用或拒绝时保留文件并提示完整路径。
不使用永久删除兜底，不自动清空回收站、保留目录或备份目录。
回收站中可能显示暂存名称；日志记录源、目标、暂存及回收前位置，可用来对应原名称。
移动源留在回收站或保留目录，会额外占用空间。撤销不依赖回收站内容。

“撤销上一批”先检查所有目标、旧备份、原位置及哈希；冲突时停止，不覆盖后来产生的文件。
撤销移动会先核验复制回源目录，整批恢复成功后才回收目标暂存。
取消后请等回滚完成再关窗口，不要强制退出。中断后可点击“恢复中断批次”。
已提交批次如果只剩清理未完成，文件仍在目标 / 源恢复位置，暂存副本会保留，查看日志提示。

七、预设与日志
可命名保存、加载、删除，以及导入 / 导出 JSON。
只保存文件通配符、递归、筛选、大小写 / 正则 / 字段格式、扩展名保护和命名规则。
不保存源目录、目标目录及覆盖开关；加载时会关闭覆盖。
%LOCALAPPDATA%\批量文件改名助手\规则预设
%LOCALAPPDATA%\批量文件改名助手\操作日志
“查看日志文件夹”可打开日志；每批保存 JSON 与可读 TXT。
请保留日志和旧目标备份，撤销及中断恢复需要它们。

八、适用范围和实际验证
完整路径少于 260 字符，单个名称不超过 255 字符。备份及暂存路径也会检查。
遇到占用、只读、权限不足或磁盘错误会停止；请关闭正在写入同批文件的其他程序。
对 Windows EFS 加密或 NTFS 附加数据流文件，移动 / 复制会拒绝，避免静默遗漏内容；仍可原地改名。
复制保留修改时间和 Windows 创建时间，访问权限等元数据按目标目录继承，不承诺复刻全部文件系统元数据。
程序没有数字签名。代码离线，不使用外部服务器。

已编译 Windows x64 成品。此次 85 项自动测试通过、0 失败、2 项 Windows 专项因平台不支持而跳过。
自动测试仅使用新建临时模拟文件，没有访问或改动 D:/COLD ATOM。
当前环境无法启动原生 Windows GUI；系统回收站、NTFS 流、真实 Windows ACL、DPI 等仍未实机验证。
因此不能承诺任何环境、磁盘故障或断电下绝对不损坏。已测与未测内容详见“测试报告.txt”。

九、本机环境自检怎样使用
运行 EXE 后点击顶部“环境与安全自检”，程序切换到预览页，显示进度并允许取消。
自检只在本机临时目录的 BRA_Check_随机编号 中创建少量模拟文件，不读取你选择的源、目标目录，也不改原来的操作日志。
完成后直接显示结果，并保存“自检报告.txt”、模拟文件和模拟批次日志。
“通过”表示这一项在当前临时目录完成；“提示”例如回收站不可用，会保留文件；“失败”会给出具体原因。
真实 Windows 系统回收站只能在你的 Windows 上完成这种本机验证。这里交付前执行的是 Linux 自检流程和回收站模拟测试。
自检不能保证其他磁盘、网络盘、Windows ACL 或断电条件都相同。

启动诊断默认位置：%LOCALAPPDATA%\批量文件改名助手\诊断日志。
该位置不可写时会尝试把诊断文本保存到系统临时目录，错误弹窗会显示实际位置。
若 Windows 在程序进入启动代码前就阻止 EXE 运行，则程序尚无法生成诊断日志。
本程序已附带运行库，但没有 Windows 原生实机验收，不能承诺所有系统环境均无问题。

路径接近 260 字符时，清理文件可能保留为原目录中的 .__bra_k_随机编号.bin，避免较长保留目录无法创建。
具体位置在“最近批次详情”和日志中；仍不会永久删除。该软件临时名称不会参加后续扫描。
